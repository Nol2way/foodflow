# ระบบสต็อกร้านอาหารทะเล (Plato)

> ⚠️ **เอกสารเดิม (0019-0025)** ถูกแทนที่ด้วยโมดูลสต็อกแบบ ledger + ล็อต ใน [stock.md](stock.md) (0027-0030): ไม่มีการบันทึกของเสียแยก ไม่มีการผลิตของเตรียม (ใช้สูตรย่อยแทน) ต้นทุนเป็น FIFO ตามล็อต หน่วยฐานเป็น g/ml/pcs และยกเลิกออเดอร์แล้วคืนสต็อก · ตารางการย้ายข้อมูลอยู่ที่ stock.md ข้อ 7 · ส่วนที่ยังใช้อยู่: ใบรับของตรวจเทียบบิล/ยอดทวง (0025) ขายตามน้ำหนัก หน่วยแปลง

ออกแบบเพื่อแก้ 3 ปัญหาหลักของอาหารทะเล: น้ำหนักวัตถุดิบผันผวน ของเสียสูง และปริมาณต่อจานไม่คงที่
โดยตรวจสอบแบบชุดใหญ่ (Mass Variance) ระหว่างการตรวจนับ 2 ครั้ง (รายสัปดาห์หรือรายเดือน)

migration: `0019` ประวัติสต็อก · `0022` ใบตรวจนับ · `0023` Yield %, ของเตรียม, ใบรับของ, ของเสียแยกประเภท, ขายตามน้ำหนัก, รายงานส่วนต่าง

## 1. โครงสร้างฐานข้อมูล

### `ingredients` วัตถุดิบหลัก

| คอลัมน์ | หน้าที่ |
|---|---|
| `name`, `unit` | ชื่อ และหน่วยนับสต็อก (kg, g, ml, ชิ้น) |
| `category` | หมวด เช่น อาหารทะเล ผัก ซอส |
| `quantity_on_hand` | คงเหลือในระบบ (แก้ตรงไม่ได้ ต้องผ่าน `stock_movements`) |
| `cost_per_unit` | ต้นทุนต่อหน่วย (เฉลี่ยถ่วงน้ำหนัก อัปเดตทุกครั้งที่รับของ) |
| `yield_pct` | % ส่วนที่ใช้ได้จริงหลังแกะ/ล้าง/ตัดแต่ง เช่น ปูม้า 35, กุ้งแกะเปลือก 60, มะนาว (คั้นน้ำ) 40 |
| `variance_threshold_pct` | เกณฑ์เตือนส่วนต่าง ± % (ค่าเริ่มต้น 5) |
| `reorder_level` | แจ้งเตือนใกล้หมด |
| `is_prep`, `batch_output_qty` | เป็นของเตรียม/สูตรย่อย และผลิต 1 ถังได้เท่าไร |

### `recipes` สูตรอาหาร · `prep_components` สูตรย่อย

| ตาราง | คอลัมน์ | หน้าที่ |
|---|---|---|
| `recipes` | `menu_item_id`, `ingredient_id`, `quantity_used` | **น้ำหนักสุทธิ** ที่ใส่จริงต่อ 1 จาน (ระบบตัดดิบ = สุทธิ ÷ Yield%) |
| `prep_components` | `prep_id`, `ingredient_id`, `quantity` | ส่วนผสมสุทธิต่อ 1 ถังของของเตรียม |
| `prep_batches` | `prep_id`, `output_qty`, `produced_by_name`, `created_at` | บันทึกการผลิตแต่ละครั้ง |

### `stock_receipts` + `stock_receipt_lines` ใบรับของ

| คอลัมน์ | หน้าที่ |
|---|---|
| `supplier`, `invoice_no`, `received_on` | ผู้ขาย เลขบิล วันที่รับ |
| `quantity`, `unit_cost`, `line_total` | น้ำหนักชั่งจริงตอนรับ ราคาต่อหน่วย รวม |
| `total_cost`, `expense_id` | ยอดรวม และรายจ่ายที่บันทึกในบัญชีให้อัตโนมัติ |

### `stock_movements` ทุกการเคลื่อนไหว (รวมของเสียประจำวัน)

| คอลัมน์ | หน้าที่ |
|---|---|
| `change` | บวก = เข้า ลบ = ออก |
| `reason` | `purchase` รับเข้า · `sale` ตัดขาย · `waste` ของเสีย · `adjustment` ปรับยอด · `production` ผลิตของเตรียม |
| `waste_type` | ประเภทของเสีย: `spoiled` เน่า/ตาย · `trim` ตัดแต่ง · `dropped` ตกหล่น · `returned` ลูกค้าคืน · `expired` หมดอายุ · `other` |
| `balance_after`, `created_by`, `note` | คงเหลือหลังรายการ คนทำ หมายเหตุ |
| `order_id`, `receipt_id`, `count_id`, `batch_id` | ที่มาของรายการ |

### `stock_counts` + `stock_count_lines` ยอดนับจริง (Physical Stocktake)

| คอลัมน์ | หน้าที่ |
|---|---|
| `system_qty` | ยอดในระบบ ณ ตอนนับ |
| `counted_qty` | ยอดนับได้จริง |
| `diff`, `unit_cost` | ส่วนต่าง และต้นทุนตอนนับ |

### `units` + `ingredient_units` หน่วยนับ (0024)

| ตาราง | คอลัมน์ | หน้าที่ |
|---|---|---|
| `units` | `name` | หน่วยกลางของร้าน (kg, g, ลิตร, ตัว, ลัง ...) เป็นตัวเลือกตอนสร้างวัตถุดิบ |
| `ingredient_units` | `unit_name`, `factor` | หน่วยแปลง: 1 `unit_name` = `factor` × หน่วยหลัก เช่น กุ้ง 1 ลัง = 10 kg |
| `stock_receipt_lines` | `entered_unit`, `entered_qty`, `entered_unit_cost` | ที่กรอกจริงตอนรับ (3 ลัง @ ฿400/ลัง) คู่กับค่าที่แปลงแล้ว (30 kg @ ฿40/kg) |
| `stock_count_lines` | `entered_text` | ที่นับจริง เช่น "2 ลัง + 3.5 kg" |

สต็อก สูตร และรายงานใช้หน่วยหลักหน่วยเดียวเสมอ หน่วยแปลงใช้แค่ตอนกรอก

### ของขายตามน้ำหนัก

| ตาราง | คอลัมน์ | หน้าที่ |
|---|---|---|
| `menu_items` | `sold_by_weight`, `weight_ingredient_id` | ขายตามน้ำหนัก (`price` = ราคาต่อ 1 กก.) และวัตถุดิบที่ตัด |
| `order_items` | `weight_g` | น้ำหนักที่ชั่งจริง (1 บรรทัด = 1 ครั้งที่ชั่ง) |

## 2. สูตรคำนวณล็อตใหญ่ (Mass Variance)

งวด = ระหว่างใบตรวจนับต้นงวดกับปลายงวด ดูได้ที่หน้า **ส่วนต่างสต็อก** (`stock_variance`)

| ค่า | สูตร |
|---|---|
| ใช้จริง (Actual Usage) | ยอดนับต้นงวด + รับเข้า + ผลิตได้ − ยอดนับปลายงวด |
| ตามทฤษฎี (Theoretical Usage) | Σ (จำนวนที่ขาย × น้ำหนักสุทธิต่อจาน ÷ Yield%) + น้ำหนักที่ชั่งขาย + ส่วนผสมที่ใช้ผลิตของเตรียม |
| ส่วนต่าง (Variance) | ใช้จริง − ตามทฤษฎี (บวก = ใช้เกินสูตร/ของหาย) |
| ส่วนต่าง % | ส่วนต่าง ÷ ตามทฤษฎี × 100 |
| หายไม่ทราบสาเหตุ | ส่วนต่าง − ของเสียที่บันทึก |
| สถานะ | \|ส่วนต่าง %\| > เกณฑ์ของวัตถุดิบ (±5%) = **เตือน (แดง)** |

ตามทฤษฎีคิดย้อนจากออเดอร์ที่ครัวเริ่มทำในงวด (Reverse Calculation) ด้วยสูตรปัจจุบัน และไม่ถูกจำกัดด้วยสต็อกที่มี

### สูตร Google Sheets (ถ้าต้องการตรวจซ้ำนอกระบบ)

ส่งออก CSV จากหน้า **ส่วนต่างสต็อก** ได้เลย หรือสร้างเองด้วยชีตเหล่านี้:
`Ingredients` (B ชื่อ · C หน่วย · D yield% · E ต้นทุน · F เกณฑ์%), `Recipes` (A เมนู · B วัตถุดิบ · C สุทธิต่อจาน),
`Sales` (A วันที่ · B เมนู · C จำนวน), `Receiving` (A วันที่ · B วัตถุดิบ · C จำนวน), `Stocktake` (A วันที่ · B วัตถุดิบ · C นับได้)

ชีต `Variance`: `B1` = วันนับต้นงวด, `B2` = วันนับปลายงวด, วัตถุดิบเริ่มที่ `A5` (ทุกหน่วยในสูตรต้องตรงกับหน่วยสต็อก)

| คอลัมน์ | สูตร (แถว 5) |
|---|---|
| B ต้นงวด | `=SUMIFS(Stocktake!C:C, Stocktake!B:B, A5, Stocktake!A:A, $B$1)` |
| C รับเข้า | `=SUMIFS(Receiving!C:C, Receiving!B:B, A5, Receiving!A:A, ">"&$B$1, Receiving!A:A, "<="&$B$2)` |
| D ปลายงวด | `=SUMIFS(Stocktake!C:C, Stocktake!B:B, A5, Stocktake!A:A, $B$2)` |
| E ใช้จริง | `=B5+C5-D5` |
| F ตามทฤษฎี | `=SUMPRODUCT((Recipes!$B$2:$B=A5) * Recipes!$C$2:$C * SUMIFS(Sales!$C:$C, Sales!$B:$B, Recipes!$A$2:$A, Sales!$A:$A, ">"&$B$1, Sales!$A:$A, "<="&$B$2)) / (VLOOKUP(A5, Ingredients!$B:$D, 3, FALSE)/100)` |
| G ส่วนต่าง | `=E5-F5` |
| H ส่วนต่าง % | `=IF(F5=0, "", G5/F5)` (จัดรูปแบบเป็น %) |
| I สถานะ | `=IF(F5=0, IF(E5=0, "ไม่มีการใช้", "⚠ เตือน"), IF(ABS(H5) > VLOOKUP(A5, Ingredients!$B:$F, 5, FALSE)/100, "⚠ เกินเกณฑ์", "ปกติ"))` |
| J มูลค่าส่วนต่าง | `=G5*VLOOKUP(A5, Ingredients!$B:$E, 4, FALSE)` |

ทำให้แถวเป็นสีแดง: Format → Conditional formatting → ช่วง `A5:J` → Custom formula `=AND($H5<>"", ABS($H5)>0.05)`

### ตัวอย่างตัวเลข 1 สัปดาห์

**ปูม้า** (หน่วย kg · yield 35% · ต้นทุน 350 บาท/kg · เกณฑ์ ±5%)

| รายการ | คำนวณ | ผล |
|---|---|---|
| ใช้จริง | 25 (ต้นงวด) + 60 (รับ) − 18 (ปลายงวด) | 67.000 kg |
| ปูนึ่งชั่งขาย | น้ำหนักที่ชั่งรวมทั้งสัปดาห์ | 38.500 kg |
| ผัดผงกะหรี่ 120 จาน | 120 × 0.080 kg (เนื้อปูสุทธิ) ÷ 35% | 27.429 kg |
| ตามทฤษฎี | 38.500 + 27.429 | 65.929 kg |
| ส่วนต่าง | 67.000 − 65.929 = 1.071 kg (1.62%) | **ปกติ** · มูลค่า 375 บาท |

**กุ้งสด** (หน่วย kg · yield 60% · ต้นทุน 400 บาท/kg · เกณฑ์ ±5%)

| รายการ | คำนวณ | ผล |
|---|---|---|
| ใช้จริง | 12 + 40 − 9 | 43.000 kg |
| กุ้งกระเทียม 150 จาน | 150 × 0.150 ÷ 60% | 37.500 kg |
| ต้มยำกุ้ง 10 หม้อ | 10 × 0.100 ÷ 60% | 1.667 kg |
| ตามทฤษฎี | 37.500 + 1.667 | 39.167 kg |
| ส่วนต่าง | 43.000 − 39.167 = 3.833 kg (9.79%) | **เกินเกณฑ์ (แดง)** · มูลค่า 1,533 บาท |
| ของเสียที่บันทึก | กุ้งเน่า 1.5 kg | หายไม่ทราบสาเหตุ 2.333 kg |

สิ่งที่ควรตรวจเมื่อเกินเกณฑ์: ตักต่อจานเกินสูตรไหม · Yield% ที่ตั้งยังตรงกับของล็อตนี้ไหม (กุ้งตัวเล็กลง yield ต่ำลง) · ชั่งตอนรับของตรงบิลไหม · ของเสียที่ไม่ได้บันทึก

## 3. น้ำจิ้มซีฟู้ด และของขายตามน้ำหนัก

### น้ำจิ้มซีฟู้ด (ผลิตทีละถัง ตักขายเป็นถ้วย)

1. เพิ่มวัตถุดิบ "น้ำจิ้มซีฟู้ด" หน่วย g ติ๊ก **ของเตรียม** และกรอก "1 ถังได้ 5000"
2. กำหนดส่วนผสมต่อถัง (น้ำหนักสุทธิ) เช่น น้ำมะนาว 1000 g (มะนาว yield 40%) · พริก 300 g · กระเทียม 400 g
3. ทำน้ำจิ้มแล้วกด **ผลิต** (เจ้าของ สต็อก หรือครัว): ผลิต 2500 g = ครึ่งถัง ระบบตัดมะนาว 1000 × 0.5 ÷ 40% = 1250 g, พริก 150 g, กระเทียม 200 g แล้วเพิ่มน้ำจิ้ม 2500 g
4. ใส่น้ำจิ้มในสูตรเมนู เช่น ปูนึ่ง 30 g ต่อถ้วย ขายแล้วตัดน้ำจิ้ม ไม่ตัดมะนาวซ้ำ

รายงานส่วนต่างตรวจได้ 2 ชั้น: **น้ำจิ้ม** (ผลิตได้ เทียบกับตักขายตามสูตร = ตักเกินไหม) และ **มะนาว พริก กระเทียม** (ใช้จริง เทียบกับที่ควรใช้ผลิต = ทำน้ำจิ้มเกินสูตรไหม)

### ขายตามน้ำหนักจริง (ปู/ปลาสดหน้าตู้)

1. หน้าจัดการเมนู: ติ๊ก **ขายตามน้ำหนักจริง** ราคา = ราคาต่อ 1 กก. และเลือกวัตถุดิบที่ตัด (หน่วย g หรือ kg)
2. หน้ารับออเดอร์: แตะเมนู แล้วกรอกน้ำหนักที่ชั่ง (เช่น 1.250 กก.) ได้ราคา 800 × 1.25 = 1,000 บาท ชั่งหลายตัวได้หลายบรรทัด
3. ฐานข้อมูลคิดราคาซ้ำจากน้ำหนัก (ไม่เชื่อราคาจากหน้าเว็บ) และเมื่อครัวเริ่มทำ ตัดสต็อกตามน้ำหนักจริง (1.25 กก.) ไม่หาร Yield เพราะลูกค้าซื้อทั้งตัว
4. ครัว เสิร์ฟ และหน้ารับชำระแสดงน้ำหนักแทนจำนวน เช่น "1.25 กก. · ปูม้านึ่ง"

## 4. นับ 2 แบบ (0025)

### แบบที่ 1: นับตอนรับเข้า (ใบรับของ เทียบบิล)

ชั่ง/นับก่อนเซ็นรับ ของที่คิดเงินตามน้ำหนักให้ชั่งเองโดยเอาน้ำแข็งและบรรจุภัณฑ์ออก ไม่เชื่อน้ำหนักบนลัง

| ช่อง | ความหมาย |
|---|---|
| ตามบิล | จำนวน + หน่วยบนบิล (เลือกหน่วยใดก็ได้ หน่วยใหม่กรอก "1 ลัง = ? kg" แล้วระบบเก็บเป็นหน่วยแปลงของวัตถุดิบ) + ราคาต่อหน่วยบนบิล |
| รับจริง | น้ำหนัก/จำนวนที่ชั่งเอง (หน่วยหลัก) · ของแช่แข็งกรอกน้ำหนักรวมและสุทธิหลังละลาย → % น้ำแข็ง |
| ผล | ห่างจากบิลเกินเกณฑ์ (ค่าเริ่มต้น ±2%) = ขาด/เกิน · รับ 0 = ตีกลับ |
| รอทวง | (ตามบิล − รับจริง) × ราคา → ติดตามสถานะ รอทวง / ได้ลดหนี้แล้ว / ยอมรับ ไม่ทวง |

- สต็อกเพิ่มตาม **รับจริง** · ต้นทุนเฉลี่ยคิดจากรับจริง × ราคาบิล
- รายจ่ายบันทึกตามยอดบิล เมื่อได้ลดหนี้ ระบบหักออกจากรายจ่ายให้
- ลังที่หนักไม่เท่ากัน ไม่ต้องแก้ตัวคูณ: กรอกน้ำหนักจริง ระบบแสดง kg ต่อลังเทียบค่าปกติให้เห็นเอง

### แบบที่ 2: นับตอนนับล่าสุด (ใบตรวจนับ)

- **รายสัปดาห์:** เฉพาะวัตถุดิบที่ติ๊ก "นับทุกสัปดาห์" (อาหารทะเล โปรตีน ของมูลค่าสูง)
- **รายเดือน:** ทุกรายการ · **เฉพาะจุด:** นับบางรายการเมื่อสงสัย

หน้าสต็อกแสดง รับเข้าล่าสุด (ขาดจากบิลเท่าไร) / นับล่าสุด (ต่างจากระบบเท่าไร) / คงเหลือในระบบ ต่อวัตถุดิบ

### รายงานผู้ขาย

ต่อผู้ขาย: ยอดบิล, ครั้งที่ขาด/ตีกลับ, % ยอดขาดของบิล (เป้าหมาย < 1%), รอทวง, ได้ลดหนี้, % น้ำแข็งเฉลี่ยถ่วงน้ำหนักและครั้งที่เกินเกณฑ์, ครั้งที่ราคาขึ้นเกิน 10% จากครั้งก่อน
