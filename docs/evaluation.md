# แบบประเมินการใช้งาน FoodFlow

> แบบประเมินสำหรับร้านนำร่อง กรอกผลหลังทดลองใช้จริงและบันทึกวันที่ รุ่นระบบ ร้าน และจำนวนผู้ตอบแต่ละบทบาท

## 1. ผู้ประเมิน

| กลุ่ม | จำนวนเป้าหมาย |
|-------|:--------------:|
| เจ้าของร้าน | 3-5 คน |
| ผู้จัดการ | ตามจำนวนผู้ที่ทดลองใช้ |
| พนักงานครัว | 3-5 คน |
| พนักงานหน้าร้านที่รับออเดอร์ | 3-5 คน |
| พนักงานบัญชีและพนักงานสต็อก | ตามจำนวนผู้ที่ทดลองใช้ แยกผลตามบทบาท |

## 2. แบบประเมินความพึงพอใจ (Likert 1-5)

1 = น้อยที่สุด · 5 = มากที่สุด ให้เลือก “ไม่ได้ทดลอง” สำหรับงานที่ผู้ตอบไม่ได้ทำ และระบุจำนวนคำตอบที่ใช้คำนวณแต่ละข้อ

### ส่วนที่ 1: ความง่ายในการใช้งาน
1. หน้าจอเข้าใจง่าย
2. ใช้งานบนมือถือได้สะดวก
3. รับออเดอร์/ทำงานได้รวดเร็วกว่าวิธีเดิม (เช่น จดกระดาษ)

### ส่วนที่ 2: ฟังก์ชันการทำงาน
4. ระบบออเดอร์และหน้าจอครัวตอบโจทย์
5. ระบบบัญชีช่วยให้เห็นกำไร-ขาดทุนชัดเจน
6. ระบบสต็อกช่วยเห็นของใกล้หมดและส่วนต่างจากการนับ
7. การนำเข้าข้อมูลเดิมทำได้ง่าย

### ส่วนที่ 3: รายงานและคำแนะนำโปรโมชัน
8. รายงานรายวันช่วยให้ติดตามยอดขายได้
9. คำแนะนำโปรโมชันเข้าใจง่ายและนำไปใช้ได้
10. ตรวจสอบตัวเลขในรายงานเทียบกับยอดขายของร้านได้สะดวก

### ส่วนที่ 4: ภาพรวม
11. ความพึงพอใจโดยรวม
12. มีแนวโน้มจะใช้ต่อ
13. แนะนำให้ร้านอื่นใช้

**คำถามปลายเปิด:** ฟีเจอร์ที่ชอบที่สุด · ปัญหาที่เจอ · สิ่งที่อยากให้เพิ่ม · ยอมจ่ายต่อเดือนประมาณเท่าไร

## 3. ตัวชี้วัดเชิงปริมาณ (เก็บจากระบบ)

| ตัวชี้วัด | วิธีวัด | ผล |
|-----------|---------|:--:|
| เวลาจากส่งออเดอร์ถึงครัวเห็น | จับเวลาจากกดส่งถึงออเดอร์แสดงบนจอครัว | |
| ความคลาดเคลื่อนของคาดการณ์จำนวนออเดอร์ (MAPE) | หากทดลองใช้ `forecastForDay` ให้เทียบผลย้อนหลังกับจำนวนออเดอร์จริงนอกหน้าเว็บ ระบุช่วงข้อมูลและวิธีจัดการช่วงที่ยอดจริงเป็นศูนย์ | |
| เวลาที่เจ้าของร้านใช้ทำบัญชีต่อวัน (ก่อน/หลังใช้) | สัมภาษณ์ + จับเวลา | |
| ส่วนต่างสต็อกจากการนับ | เปรียบเทียบ `variance_qty` และ `variance_value` ของวัตถุดิบชุดเดียวกันในแต่ละรอบ | |
| เหตุการณ์ของหมดหรือทิ้งวัตถุดิบก่อนและหลังใช้ | ใช้บันทึกหน้างานในช่วงที่เทียบกันได้ เพราะส่วนต่างจากใบนับรวมหลายสาเหตุ | |
