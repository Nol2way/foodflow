> ตรวจเมื่อ 22 ต.ค. 2569 เทียบกับโค้ดจริงใน repo (ไม่ได้ดูจากเอกสารอย่างเดียว)

## 1. ที่มาของ requirement

| รหัส | ความต้องการจากเจ้าของโครงงาน |
|------|------------------------------|
| R1 | ระบบร้านอาหาร **บัญชีเป็นหลัก** รองลงมาคือ **เช็คสต็อก** |
| R2 | AI ช่วยคาดการณ์ว่าช่วงไหนลูกค้ามาเยอะ จากสถิติร้าน ("โยนข้อมูลเข้า แล้วให้วิเคราะห์") |
| R3 | เช็คอาหารที่ลูกค้าสั่ง (ออเดอร์/ครัว) |
| R4 | ขายระบบได้ (เป็นซอฟต์แวร์ให้หลายร้าน) |
| R5 | repo GitHub รูปแบบเดียวกับโปรเจกต์ตัวอย่าง พร้อมเอกสารและ README |
| R6 | บทบาทผู้ใช้ทั้งหมด แยกพนักงานบัญชี และพนักงานสต็อก |
| R7 | วิเคราะห์ข้อมูลลูกค้า ช่วงพีค/ออฟพีค |
| R8 | backend |
| R9 | แยกเป็น frontend / backend / SQL migration / เอกสาร รวมเป็นไฟล์เดียว + Swagger |
| R10 | **ลูกค้าไม่ต้องเลือกเมนูเอง พนักงานเท่านั้นที่รับออเดอร์ เมื่อพนักงานส่งออเดอร์จะเข้าไปยังครัว** (แทนการสแกน QR สั่งเองที่ทำไว้เดิม) |
| R11 | **เพิ่มบทบาทผู้จัดการ (manager) จัดการ โปรโมชัน / พนักงาน / นำเข้า CSV / เมนู** |
