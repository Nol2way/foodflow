# โมดูลบัญชี (migration 0026)

> ⚠️ **ระบบนี้ไม่ใช่เครื่องมือยื่นภาษีอย่างเป็นทางการ** ตัวเลขภาษี (ภาษีขาย/ซื้อ เกณฑ์ VAT เหมา 60% vs ตามจริง) และงบการเงินเป็นข้อมูลประกอบการบริหารร้าน ควรให้นักบัญชีตรวจก่อนใช้ยื่นภาษีหรือส่งหน่วยงานราชการ

บัญชีคู่ (double-entry) ลงอัตโนมัติข้างหลังจากบิล สต็อก และรายจ่าย ผู้ใช้ทั่วไปไม่ต้องเห็นเดบิต/เครดิต เลือกดูได้ 3 โหมดจากข้อมูลชุดเดียวกัน

| `frontend/src/lib/accounting.ts` | สูตร Food/Prime Cost กำไร perpetual งบดุล เกณฑ์ VAT เหมา 60% แจ้งเตือน ไฟล์ส่งออก (ใช้ร่วมกับ backend) |

## 1. หลักการ

- **เดบิต = เครดิต ทุกรายการ** — ตรวจด้วย constraint trigger แบบ deferred (`journal_entries_balanced`, `journal_lines_balanced`) ตอน commit รายการที่ไม่สมดุลหรือมีไม่ถึง 2 บรรทัดจะถูกปฏิเสธทั้งธุรกรรม · 1 บรรทัดต้องเป็นเดบิตหรือเครดิตอย่างใดอย่างหนึ่ง (check constraint)
- **แก้ย้อนหลังไม่ได้** — trigger `journal_immutable` ห้าม update/delete ทั้ง `journal_entries` และ `journal_lines` (แม้ superuser) เพิ่มบรรทัดได้เฉพาะรายการที่สร้างในธุรกรรมเดียวกัน ผู้ใช้เขียนตารางตรงไม่ได้ (revoke) ต้องผ่านฟังก์ชันเท่านั้น · แก้ไขด้วย **reversal entry** (`source_type = 'reversal'`, `reverses_entry_id`) กลับรายการได้ครั้งเดียว (unique index)
- **Perpetual inventory** — ซื้อวัตถุดิบเข้าเป็นสินทรัพย์ (1130) ตัดเป็นต้นทุนขาย (5010) เมื่อครัวเริ่มทำตามสูตร ปรับส่วนต่างจากการนับ/ของเสีย/ผลิตของเตรียมเข้า 5020
- **ต้นทุนขายจริง = ต้นทุนตามสูตร + ส่วนต่างสต็อก = ต้นงวด + ซื้อ − ปลายงวด** (ตรวจได้ทุกช่วงวันที่ เพราะบัญชีสต็อกเปลี่ยนจาก 3 ทางเท่านั้น: รับเข้า/ยอดยกมา, ตัดตามสูตร, ส่วนต่าง)

### บัญชีสต็อก = มูลค่าในโมดูลสต็อก เสมอ

มูลค่าสต็อกต่อวัตถุดิบนิยามเป็น `round(quantity_on_hand × cost_per_unit, 2)` trigger `ingredients_accounting` ลง **ผลต่างของมูลค่านี้** ทุกครั้งที่ยอดคงเหลือหรือต้นทุนต่อหน่วยเปลี่ยน (ไม่ว่าจะเปลี่ยนจากทางไหน) บัญชีจึงเท่ากับโมดูลสต็อกเป๊ะ ไม่มีเศษสตางค์สะสม

ประเภทเอกสารได้จาก `stock_movements` (ตั้งเป็นบริบทชั่วคราวในธุรกรรม `plato.stock_ctx` ใน `apply_stock_movement`)

| เหตุการณ์ในโมดูลสต็อก | รายการบัญชี | source_type |
|------------------------|-------------|-------------|
| ครัวเริ่มทำ (`reason = sale`) | Dr ต้นทุนขาย / Cr สต็อก | `recipe_deduct` (1 ออเดอร์ = 1 รายการ) |
| ใบรับของ (`submit_stock_receipt`) | Dr สต็อก (มูลค่าที่เพิ่มจริง) + Dr ลูกหนี้ผู้ขาย (ของขาด/ตีกลับ) ± ส่วนต่างรับสินค้า / Cr เงินสด/ธนาคาร/เจ้าหนี้ (ยอดตามบิล) | `stock_receipt` (1 ใบ = 1 รายการ) |
| ตรวจนับขาด (`adjustment` ติดลบ) | Dr ส่วนต่างสต็อก / Cr สต็อก | `count_adjust` |
| ตรวจนับเกิน | Dr สต็อก / Cr ส่วนต่างสต็อก | `count_adjust` |
| ของเสีย (`waste`) | Dr ส่วนต่างสต็อก / Cr สต็อก | `waste` |
| ผลิตของเตรียม (`production`) | ผลต่างมูลค่า (ส่วนผสมออก ของเตรียมเข้า) ↔ ส่วนต่างสต็อก | `production` |
| แก้ต้นทุนต่อหน่วย / ลบวัตถุดิบ / แก้ยอดตรงในฐานข้อมูล | ผลต่างมูลค่า ↔ ส่วนต่างสต็อก | `stock_revalue` |
| สร้างวัตถุดิบพร้อมยอดตั้งต้น | Dr สต็อก / Cr ทุนเจ้าของ | `opening` |

ใบรับของ: ระหว่างบันทึกใบ ระบบจำรหัสใบไว้ (`plato.receipt_ctx`) ต้นทุนเฉลี่ยที่เปลี่ยนก่อนสต็อกเข้าจึงลงในใบเดียวกัน และรายจ่าย "วัตถุดิบ" ที่ใบรับของสร้างให้ (`expenses.source = 'stock_receipt'`) **ไม่ลงซ้ำ** เพราะลงเป็นสต็อกแล้ว · จ่ายด้วยอะไรตั้งที่ `shop_settings.receipt_payment_default` (เงินสด / โอน / ค้างเจ้าหนี้) · ของขาดที่ติดตาม (`set_receipt_claim`) ได้ลดหนี้ = Dr เจ้าหนี้ / Cr ลูกหนี้ผู้ขาย · ยอมรับ = Dr ส่วนต่างรับสินค้า / Cr ลูกหนี้ผู้ขาย

## 4. ปิดวัน (`day_closes`)

1. แท็บ "ปิดวัน" แสดงสรุปยอดของวัน (`acct_day_summary`) และ **เงินสดตามระบบ** = ยอดบัญชีเงินสด ณ สิ้นวัน (ยอดยกมา + ขายเงินสด − จ่ายเงินสด)
2. เจ้าของ/ผู้จัดการนับเงินในลิ้นชัก กรอกยอด แล้วยืนยัน (`acct_close_day`) ส่วนต่างลงบัญชีเงินสดขาด/เกิน บันทึกผู้ยืนยัน เวลา ยอดระบบ ยอดนับ
3. **หลังยืนยัน ล็อกวันนั้น:** ลงรายการใหม่ในวันนั้นไม่ได้ (`day_closed`) รายการอัตโนมัติที่เกิดหลังปิด (บิลจ่ายดึก ตัดสต็อก) เข้าวันถัดไป แก้ได้เฉพาะ reversal (ลงวันที่ที่ยังเปิดอยู่)
4. backend (`POST /api/accounting/day-close`) ส่งสรุปเข้า LINE ของร้าน (`shop_settings.line_to`) ถ้าตั้ง `LINE_CHANNEL_ACCESS_TOKEN` · ส่งไม่ได้ก็ยังปิดวันสำเร็จ (ตอบ `line: failed`)

## 5. 3 โหมดแสดงผล (ข้อมูลชุดเดียวกัน)

| โหมด | เห็นอะไร |
|------|----------|
| **ง่าย** | เงินเข้า / เงินออก / คงเหลือ (เงินสด + ธนาคาร) แยกตามที่มา · มุมมองเงินสด: ซื้อของ = รายจ่ายวันนั้น |
| **มาตรฐาน** (ค่าเริ่มต้น) | ยอดขาย − ต้นทุนอาหารที่ใช้จริง − ค่าใช้จ่าย = กำไร · Food Cost % (เป้า 28–35%) · Prime Cost % (เป้า 60–65%) เป็นแถบสี · ส่วนต่างสต็อก · ต้นทุนต่อจาน · เทียบกำไรเดือนก่อน |
| **มืออาชีพ** | งบกำไรขาดทุน ตรวจ perpetual และแท็บรายงาน: สมุดรายวัน บัญชีแยกประเภท งบดุล งบกระแสเงินสด ภาษีขาย/ซื้อ |

เปลี่ยนโหมดได้ตลอด (ปุ่มมุมขวาบน จำในเครื่อง) · ค่าเริ่มต้นของร้านตั้งที่แท็บตั้งค่าบัญชี · **Onboarding:** เจ้าของเปิดหน้าบัญชีครั้งแรกจะถาม "จดบริษัทไหม / จด VAT ไหม" → จดอย่างใดอย่างหนึ่ง = มืออาชีพ · ไม่จดทั้งคู่ = มาตรฐาน (หรือง่าย ถ้าเลือก)

### สูตร (`frontend/src/lib/accounting.ts`)

- ยอดขายสุทธิ = ยอดขาย (กลุ่ม sales) − ส่วนลด (กลุ่ม discount)
- ต้นทุนอาหารที่ใช้จริง = กลุ่ม food_cost (ตามสูตร + ส่วนต่างสต็อก + วัตถุดิบนอกสต็อก + ส่วนต่างรับสินค้า)
- **Food Cost %** = ต้นทุนอาหาร ÷ ยอดขายสุทธิ × 100
- **Prime Cost %** = (ต้นทุนอาหาร + ค่าแรง) ÷ ยอดขายสุทธิ × 100
- กำไรสุทธิ = ยอดขายสุทธิ + รายได้อื่น − ต้นทุนอาหาร − ค่าแรง − ค่าใช้จ่ายดำเนินงาน
- ไม่มียอดขาย → % เป็น "–" (ไม่หารศูนย์)

## 6. รายงานและแจ้งเตือน

- กำไรวันนี้ / 7 วัน / 30 วัน / เดือนนี้ เทียบเดือนก่อน (`acct_dashboard`)
- กำไรขั้นต้นต่อเมนู (`acct_menu_profit`: ยอดขายก่อนส่วนลดท้ายบิล × ต้นทุนตามสูตรปัจจุบัน)
- งบทดลอง → งบกำไรขาดทุน งบดุล (`acct_trial_balance`) · สมุดรายวัน/บัญชีแยกประเภท (`acct_journal_rows`) · กระแสเงินสดแบบทางตรง
- **แจ้งเตือน** (แสดงบนหน้าบัญชี): มูลค่าสต็อกไม่เท่าบัญชีสต็อก (`acct_stock_reconcile`) · รายรับสะสมในปีถึง 80% / เกิน 1.8 ล้านบาท (เกณฑ์จด VAT, เฉพาะร้านที่ยังไม่จด) · Food/Prime Cost 30 วันเกินเป้า · มีวันที่ยังไม่ปิดวัน
- **เหมา 60% vs ตามจริง** (แท็บรายงาน): เงินได้ − 60% เทียบ เงินได้ − ค่าใช้จ่ายจริงในบัญชี แสดงเป็นข้อมูลประกอบ ไม่ใช่คำแนะนำภาษี
- **ส่งออกให้นักบัญชี:** สมุดรายวัน งบทดลอง งบกำไรขาดทุน กำไรต่อเมนู รายจ่าย เป็น CSV (UTF-8 BOM เปิดใน Excel ภาษาไทยถูก กันสูตร Excel) หรือ Excel (`.xls` แบบ XML Spreadsheet 2003 เปิดได้ใน Excel/LibreOffice/Google Sheets)

รูปใบเสร็จอยู่ใน Storage bucket `expense-receipts` (ไม่สาธารณะ) ไฟล์ใต้โฟลเดอร์ `<restaurant_id>/` อัปโหลดได้เจ้าของ/บัญชี ดูได้เจ้าของ/ผู้จัดการ/บัญชี (หน้าเว็บเปิดด้วย signed URL 5 นาที)

## 8. ข้อจำกัดที่รู้อยู่

- วันที่ลงบัญชีของรายการสต็อกและใบรับของ = วันที่บันทึกเข้าระบบ (ตามเวลาร้าน) ไม่ใช่ `received_on` ที่กรอกย้อนหลัง
- ภาษีซื้อของใบรับของยังไม่แยก (อาหารสดส่วนใหญ่ได้รับยกเว้น VAT) ภาษีซื้อใส่ได้ที่รายจ่าย
- ใบรับของใช้วิธีจ่ายจากค่าตั้งของร้าน (ยังเลือกต่อใบไม่ได้)
- กำไรต่อเมนูใช้ต้นทุนตามสูตร **ปัจจุบัน** (ไม่ใช่ต้นทุน ณ วันที่ขาย) ส่วนต้นทุนขายในบัญชีใช้มูลค่าจริงตอนตัดสต็อก
- ร้านหลายสาขา/หลายสกุลเงิน ไม่รองรับ
