## หลักฐานสำหรับนำเสนอความคืบหน้า

1. อธิบายเส้นทางข้อมูลตามที่โค้ดทำงาน หน้า React/Vite เรียกทั้ง `/api/*` ของ Hono บน Cloudflare และ Supabase Data API/RPC ส่วนการบันทึกและกฎของธุรกรรมอยู่ใน PostgreSQL ตัวอย่างเส้นทางสาธิตคือส่งออเดอร์จาก POS ผ่าน `staff_place_order` แล้วดูออเดอร์ในครัว [การออกแบบระบบ](analysis-design.md) / [API](api.md)
2. ระบุ method, endpoint หรือ RPC และบทบาทที่ใช้ในแต่ละกรณี ตัวอย่างสำหรับรายงานคือ `GET /api/health` สำหรับเช็กบริการ และ `GET /api/auth/me` สำหรับคำขอที่ต้องยืนยันตัวตน FoodFlow ตรวจรหัสผ่านจาก `app_users` และ backend ออก JWT ส่วน RLS และฟังก์ชันฐานข้อมูลบังคับสิทธิ์ตามร้านและบทบาท ใช้บัญชีทดสอบและปิดบังข้อมูลรับรองในหลักฐาน [API และ Swagger](api.md) / [การตั้งค่า](SETUP.md)
3. แสดง schema หรือความสัมพันธ์ของข้อมูลที่ใช้ และหลักฐานว่าข้อมูลทดสอบที่เพิ่งบันทึกอ่านกลับมาได้ เช่น ออเดอร์และรายการอาหารที่จับคู่กับร้านและโต๊ะที่ถูกต้อง บันทึก commit และสภาพแวดล้อมที่ทดสอบเพื่อให้ทีมทำซ้ำได้ [ข้อกำหนด](requirements.md)
4. แนบผลทดสอบสำเร็จและผิดพลาดที่รันจริง เช่น status ของคำขอ ข้อความที่หน้าเว็บแสดง และผลตรวจสิทธิ์คนละบทบาทหรือคนละร้าน ใช้ Browser DevTools ตรวจพฤติกรรม CORS และใช้ Postman หรือ Swagger ดูสัญญา HTTP ร่วมกับชุดทดสอบ backend, frontend, PostgreSQL และ Playwright ที่มีใน repo [แผนการทดสอบ](testing.md) / [คำสั่งทดสอบ](SETUP.md#8-การทดสอบ)
5. สรุปงานเสร็จ งานที่กำลังทำ อุปสรรค และงานถัดไปตาม commit, PR, ผลทดสอบ หรือการสาธิตที่ตรวจสอบได้ ตัวเลขทดสอบย้อนหลังใน README ให้ระบุว่าเป็นผลที่เอกสารเดิมรายงาน ส่วนผลของรอบปัจจุบันให้ลงวันที่และอ้างหลักฐานของรอบนั้น [ใบงานทีมสองคน](tasks/2-people/README.md)

แบบฝึกสัปดาห์ 1-5 ระบุการส่งโค้ดและหลักฐานผ่าน dLearning ตามโจทย์ของแต่ละสัปดาห์ และสัปดาห์ 4-5 ให้นำเสนอต่อผู้สอนก่อนส่งหลักฐาน เครื่องมือและหัวข้อธุรกิจในแบบฝึกเป็นส่วนของกิจกรรมรายสัปดาห์ สำหรับรายงาน FoodFlow ให้ใช้สถาปัตยกรรมและเทคโนโลยีที่พบใน repo เป็นหลักฐาน

## รายงานรายบุคคล Quiz 2

ภาพโจทย์แนะนำให้เรียงเนื้อหาเป็นสี่ส่วน

1. **ตำแหน่งและบทบาทที่ได้รับมอบหมาย** ระบุบทบาทจริงและขอบเขตใน FoodFlow
2. **หน้าที่และความรับผิดชอบ** บอกงานที่ลงมือทำเอง โดยเชื่อมสิ่งที่ทำกับ UI, API หรือ SQL ตามงานจริง
3. **การจัดการและการทำงานร่วมกับทีม** อธิบายการวางแผน การแบ่งงาน การติดตาม และการประสานงานที่เกิดขึ้นจริง เช่น ข้อตกลงเรื่องไฟล์ร่วมและลำดับการแก้ `counter_pay_bill()`
4. **ความคืบหน้างานที่ได้รับมอบหมาย** ระบุงานที่ทำถึงแล้ว หลักฐาน ปัญหาและการแก้ร่วมกัน ขั้นตอนถัดไป และสิ่งที่เรียนรู้ ให้เจ้าของรายงานกรอกชื่อ รหัสนักศึกษา บทบาท และผลของตนเองตามจริง

| หัวข้อประเมินตามภาพ | คะแนน |
|---|---:|
| บทบาทและหน้าที่ที่ได้รับมอบหมาย | 0.50 |
| การบริหารจัดการโครงงาน | 1.00 |
| การจัดการทีม | 1.00 |
| ความคืบหน้าด้านการพัฒนาระบบ | 1.00 |
| การแก้ไขปัญหาและการทำงานร่วมกัน | 0.75 |
| การสรุปผลและประสบการณ์ที่ได้รับ | 0.75 |
| **รวม** | **5.00 (5%)** |

เกณฑ์ยก PM, Full-stack Developer, SA, QA/Tester และ React/Node.js/MySQL เป็นตัวอย่างการอธิบาย ทีมสองคนสามารถใช้หลักฐานการวางแผน การติดตาม และการตรวจงานร่วมกันตามบทบาท Fullstack ของแต่ละคนได้
