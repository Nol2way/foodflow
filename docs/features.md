# คู่มือฟีเจอร์ person-1 และ person-2

ใช้กับ migration `0001-0011` และ frontend/backend ใน PR รอบ remediation ดู [คู่มือปฏิบัติการ](operations.md) ก่อนนำขึ้นระบบจริง

## หน้าร้านและครัว

- **ตัวเลือกเมนู:** หน้าเมนูตั้งตัวเลือกพร้อมราคา POS เลือกตัวเลือกก่อนส่ง ราคาอ่านซ้ำจากฐานข้อมูลและเก็บชื่อ/ราคา ณ เวลาสั่ง ครัวและเอกสารใช้ snapshot เดิม ภาพเมนูใช้ media ที่มีอยู่แล้ว
- **ผังโต๊ะ `/tables`:** ดูโซน ตำแหน่ง จำนวนที่นั่ง สถานะและเวลาของออเดอร์ ย้าย/รวมโต๊ะโดยย้ายออเดอร์ที่ยังเปิด ขอเช็คบิลให้แคชเชียร์เห็นสถานะเด่น การแก้ผังเป็นสิทธิ์ผู้จัดการ/เจ้าของตาม RPC
- **ประวัติบิล `/bills`:** ค้นและพิมพ์ใบเสร็จเดิม แก้ออเดอร์ได้ก่อนครัวเริ่ม แยกบรรทัดเป็นบิลใหม่ในสถานะที่รองรับ; ห้ามแบ่งข้อมูลที่ฐานข้อมูลไม่สามารถรักษาราคา/สต็อก/เอกสารได้ เจ้าของยกเลิกบิลพร้อมเหตุผลและเงื่อนไขใบลดหนี้เดิม
- **ค่าบริการและทิป:** บันทึกก่อนชำระ ยอด Counter และใบเสร็จรวมค่าใช้จ่ายเหล่านี้ หน้าหารเท่ากันแจกเศษสตางค์ให้ผลรวมตรงยอดบิล ต้องรับครบก่อนยืนยันชำระครั้งเดียว ยังไม่ใช่รับชำระบางส่วนหลายวิธี
- **ครัว:** พิมพ์ ticket 80 มม. พร้อมตัวเลือกเมนู ตั้งเวลาเตือน เปิดเสียง และเปิดเรียก print dialog อัตโนมัติ เบราว์เซอร์/เครื่องพิมพ์อาจต้องตั้งค่าสิทธิ์เอง การเริ่มเสียงต้องมีการกดของผู้ใช้

## ออฟไลน์และประวัติ

บิลที่แยกและมีส่วนลดจะเก็บส่วนลดที่จัดสรรไว้ ห้ามเปลี่ยนโปร แก้รายการ หรือยกเลิกบางบรรทัดจนคำนวณส่วนลดเดิมซ้ำ ให้ใช้การชำระแยกบิลที่ Counter หรือยกเลิกทั้งบิลตามสิทธิ์

แอปมี manifest และ service worker สำหรับ app shell เท่านั้น ไม่ cache API response/token เมนูออฟไลน์ใช้ snapshot ต่อผู้ใช้/ร้านอายุไม่เกิน 24 ชั่วโมง POS บันทึกออเดอร์ลง IndexedDB ก่อนส่ง ใช้ `client_ref` เดิมทุกครั้งที่ retry เพื่อไม่สร้างออเดอร์ซ้ำเมื่อ response หาย

คิวรอส่ง **ยังไม่เข้าครัว** กลับมาออนไลน์แล้วตรวจรายการและกดส่งรายการค้างด้วยบัญชี/ร้านเดิม ฐานข้อมูลตรวจสิทธิ์ เมนู ราคาและโปรใหม่ ถ้าตรวจไม่ผ่านรายการยังอยู่ในคิวให้แก้กระบวนการก่อนลองใหม่ การลบคิวจากเครื่องไม่ยกเลิกออเดอร์ที่เคยส่งสำเร็จแล้ว ต้องตรวจประวัติบิลก่อนสั่งใหม่

`/audit` แสดงผู้ทำ เวลา ตาราง/รายการ และชื่อฟิลด์ที่เปลี่ยน เฉพาะ owner/manager ประวัติแก้หรือลบผ่าน app role ไม่ได้ ไม่บันทึกรหัสผ่านหรือค่าข้อมูลสมาชิกลง audit details

## สมาชิกและโปรโมชัน

- ตั้ง `coupon_code` ต่อร้านและเลือกว่าจะใช้ร่วมกับโปรอื่นได้หรือไม่ กรอกรหัสในกล่องโปร POS/Counter; คูปองไม่ถูกเลือกอัตโนมัติโดยไม่มีการกรอก
- รายงานรายวันมีผลโปร (จำนวนใช้ ส่วนลด ยอดขายที่ผูกกับโปร) บิลใช้หลายโปรอาจถูกนับในแต่ละโปร จึงห้ามบวกยอดนี้เป็นยอดขายสุทธิรวมร้าน
- ค้นสมาชิกด้วยเบอร์เต็มหรือท้าย 4 ตัว ถ้าตรงหลายคนต้องเลือกยืนยันคนที่ถูกต้อง ไม่เลือกคนแรกให้อัตโนมัติ
- หน้า Members ให้เจ้าของ export JSON และลบข้อมูลสมาชิกหลังตรวจตัวผู้ขอ การลบถอนการผูกกับประวัติธุรกรรม แต่ไม่ทำลายเอกสารการเงินที่ต้องเก็บ ดู `/privacy` และกำหนดนโยบายจริงของร้านเพิ่มเติม
- หลังชำระมีคะแนน 1-5 ดาว ไม่เก็บชื่อ/เบอร์ สรุปในรายงานรายวัน การ retry ใช้รหัสเดิมเพื่อไม่ลงคะแนนซ้ำ

## รายงานและนำเข้า

Settings เปิด morning digest และเลือกชั่วโมงตาม timezone ร้าน รายงานใช้ยอดวันก่อน เมนูขายดี สต็อกต่ำและล็อตใกล้หมดอายุ Worker Cron ต้องถูก deploy และตั้ง LINE token/ผู้รับจึงส่งจริง การส่งซ้ำอาศัย durable dispatch และ LINE retry key

Import รองรับ CSV และ `.xlsx` แผ่นงานเดียว สูงสุด 3 MB ใช้หัวคอลัมน์เดียวกัน ทั้งสองชนิดใช้ validation/preview เดียวกัน เปลี่ยนไฟล์หรือ options ต้อง preview ใหม่ ก่อน commit ส่ง `preview_token` ที่ผูกกับข้อมูลและราคา เมื่อ retry batch เดิมต้องไม่เพิ่มประวัติซ้ำ

## ภาษาและรูปแบบ

Settings → หน้าตาและภาษา เลือก System/Light/Dark และ TH/EN เก็บค่าในเครื่องและติดตามการเปลี่ยนจากแท็บอื่น ข้อความ UI ใช้ translation catalog ข้อมูลที่ผู้ใช้กรอก เช่น ชื่อเมนู ลูกค้า หมายเหตุ และหัวใบเสร็จคงเดิม งานพิมพ์ใช้พื้นขาว ตัวอักษรดำ ค่าอ้างอิงภาษี/ชื่อบัญชีที่เป็นข้อมูลในฐานไม่เปลี่ยนด้วยตัวเลือกภาษา

## API และการจัดการบัญชี

เพิ่ม HTTP สำหรับร่างภาษี tax settings/terminals, ประวัติกะ/X report, claim และรายงานผู้ขาย, member privacy/feedback/coupon/report และ active account ดู [OpenAPI](openapi.json) จาก source เป็นรายการ authoritative

Reset/ปิดบัญชีที่ใช้หลายร้านต้องผ่านกระบวนการจัดการ identity ที่มีสิทธิ์เหมาะสม ผู้ดูแลร้านหนึ่งไม่ได้รับรหัสผ่านของ global account ที่มีสิทธิ์ร้านอื่น บัญชีที่ตั้งรหัสใหม่/reset/ปิดใช้ยกเลิก token เก่า ทั้ง Worker และ RLS ตรวจสถานะและ session version
