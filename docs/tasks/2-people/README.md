## ฐานโค้ดก่อนเริ่มงาน

Migration ที่ใช้งานอยู่คือ `database/migrations/0001_*.sql` ถึง `0008_fix_accounting_stock.sql` ให้เรียงตามเลขและใช้ `archive/` เป็นประวัติอ้างอิง `0008` มีการแก้รายจ่ายที่ยกเลิกในรายงาน การยกเลิกบิลที่มีใบกำกับภาษียืนยันแล้ว และยอดรายบรรทัดใน ETDA XML

- `backend/src/app.ts` มี CORS สำหรับ `PUT` และแปลง SQLSTATE `23514`/`23503` เป็น HTTP 400 ส่วน `backend/src/accounting.ts` และ `backend/src/stock.ts` มีการตรวจข้อมูลบัญชีและรับของเพิ่มแล้ว
- หน้า `AcctReports.tsx`, `StockCount.tsx`, `StockHistory.tsx` และ `StockReceive.tsx` มีการแก้การแสดงรายงาน การเก็บร่าง การกดซ้ำ หรือผลตอบกลับเก่าตามหน้าที่ของแต่ละหน้า
- สถานะในใบงานมาจากการอ่านซอร์ส บันทึกผลทดสอบรอบปัจจุบันตาม [วิธีทดสอบ](../../testing.md) ก่อนติ๊กงานว่าเสร็จ

## การประสานงานและลำดับ Migration

- คนที่ 1 รวมการแก้ `counter_pay_bill` สำหรับ `P1-B1` และ `P1-B4` ในเฟส 1 จากนั้นคนที่ 2 ต่อยอดตัวตรวจและคำนวณโปรโมชันใน `P2-F1` เฟส 2 โดยยึดผลจากเฟส 1 และประสานกับ `P1-F1` เรื่องส่วนลดบนรายการที่มี Add-ons
- ในเฟส 3 ให้ `P1-F3` รวมค่าบริการและทิปใน `counter_pay_bill` ก่อน หากคูปองต้องเปลี่ยนฟังก์ชันรับชำระ ให้คนที่ 2 ต่อจากนิยามล่าสุดของ `P1-F3` ใน migration ช่วง `0020-0029` แล้วตรวจร่วมกับแต้ม ส่วนลด ค่าบริการ และทิป
- `P1-F5` ใช้ `staff_place_order` ที่รวม Add-ons จาก `P1-F1` แล้ว ให้ทดสอบคิวออฟไลน์กับเส้นทางปกติและกติกาโปรโมชันจาก `P2-F1`
- ใช้ branch แยกตามงานและ merge ผ่าน PR ประสานก่อนแก้ `frontend/src/App.tsx`, `frontend/src/lib/roles.ts` หรือ `backend/src/openapi.ts` ตรวจลำดับบนฐานข้อมูลใหม่และวางแผนรัน migration บนฐานใช้ร่วมกันก่อนปล่อยงานที่มี dependency
- คำนวณราคาและยอดเงินในฐานข้อมูล เปิด RLS และแยกข้อมูลตาม `restaurant_id` สำหรับตารางของร้าน ฟังก์ชัน `security definer` ให้กำหนด `search_path = public, pg_temp` และตรวจสิทธิ์ในฟังก์ชัน ประสานเจ้าของโมดูลก่อนเปลี่ยนกติกาบัญชีหรือสต็อก
- เมื่อแก้หรือเพิ่ม HTTP endpoint ให้อัปเดตส่วนที่เกี่ยวข้องใน OpenAPI และใช้ `npm --prefix backend run openapi` ออกรายการใหม่

## แผนงาน 3 เฟส

| เฟส | คนที่ 1 | คนที่ 2 |
|---|---|---|
| 1 - ปิดบั๊กและวาง CI | `P1-B1` ถึง `P1-B6` | `P2-B1` ถึง `P2-B6` และ CI ใน `P2-F5` |
| 2 - ฟีเจอร์แกนหลัก | `P1-F1` ตัวเลือกเมนูและรูป, `P1-F2` ผังโต๊ะ, `P1-F4` งานพิมพ์และแจ้งเตือนครัว | `P2-F1` คูปอง กติกาซ้อนโปร และรายงานผลโปร, `P2-F2` สมาชิก/PDPA/Feedback, `P2-F4` โหมดมืดและ TH/EN |
| 3 - ฟีเจอร์ขั้นสูง | `P1-F3` แก้ออเดอร์ แยกบิล ประวัติบิล และทิป, `P1-F5` Audit Log และ PWA | `P2-F3` สรุปเช้า LINE และ `.xlsx`, API/UI ใน `P2-F5` และจุดเชื่อมคูปองกับการรับชำระหากจำเป็น |

## เกณฑ์ส่งมอบแต่ละงาน

1. รัน `npm --prefix backend run typecheck`, `npm --prefix backend test`, `npm --prefix frontend run build` และ `npm --prefix frontend test`
2. งาน SQL ต้องรัน migration จากฐานเปล่าและทดสอบสิทธิ์ด้วย `npm run test:database` ตาม [คู่มือติดตั้ง](../../SETUP.md) งานที่แก้ข้อมูลเดิมให้ทดสอบอัปเกรดจาก schema เดิมด้วย
3. ทดสอบเส้นทางที่เปลี่ยนบน Supabase สำหรับทดสอบแล้วบันทึกผลใน [แผนทดสอบ](../../testing.md) อัปเดต [สถานะความต้องการ](../../requirements.md) และติ๊กงานเมื่อผ่านเกณฑ์ที่เกี่ยวข้อง
