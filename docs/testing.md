# แผนการทดสอบ FoodFlow

> สถานะ: **แผนการทดสอบ** ผลการทดสอบจริงให้กรอกในตารางด้านล่างหลังทดสอบแล้ว (ช่อง "ผล" ปล่อยว่างไว้ก่อน ห้ามกรอกก่อนทดสอบจริง)

## 1. ระดับการทดสอบ

| ระดับ | สิ่งที่ทดสอบ | เครื่องมือ |
|-------|--------------|------------|
| Unit | ฟังก์ชันคำนวณ ตัวอ่าน CSV | `node:test` (Node 22.18+) |
| Integration | API (จำลองบริการภายนอก) + ฐานข้อมูล (Postgres ในเครื่อง) | `node:test` + Python (`database/tests`) |
| Security | RLS แยกข้อมูลร้าน, สิทธิ์ตามบทบาท | SQL test + ทดสอบด้วยมือ |
| UAT | ผู้ใช้จริงที่ร้านนำร่อง | แบบฟอร์ม UAT |

## 3. แผน UAT (ร้านนำร่อง)

1. ให้เจ้าของร้านและพนักงานใช้งานจริงอย่างน้อย 2-4 สัปดาห์
2. ให้ทำงานตามสถานการณ์: รับออเดอร์ ปิดยอดวัน บันทึกรายจ่าย ดูรายงาน
3. สังเกตและจดจุดที่ผู้ใช้สับสนหรือต้องถามซ้ำ
4. เก็บแบบประเมินตามแบบใน [evaluation.md](evaluation.md)

### ทดสอบหน้าเว็บด้วยข้อมูลจำลอง (ทำแล้ว)

รอบผู้จัดการ: เมนูที่ผู้จัดการเห็น, หน้าจัดการเมนู (ไม่เห็นส่วนโต๊ะ), หน้าโปรโมชัน, หน้าพนักงาน (เลือกได้เฉพาะ 4 บทบาท แก้เจ้าของ/ตัวเองไม่ได้), ผู้จัดการเข้าหน้าครัวไม่ได้, หน้ารับออเดอร์เลือกโปรแล้วแสดงเงื่อนไขขั้นต่ำและส่วนลด ส่ง `p_promotion_id` ถูกต้อง

เปิดหน้าเว็บจริงในเบราว์เซอร์ (Chromium) โดยจำลองการตอบของ Supabase: หน้ารับออเดอร์เลือกโต๊ะ เพิ่มเมนู ใส่หมายเหตุ กดส่งเข้าครัว และสั่งกลับบ้าน → ตรวจว่าส่งข้อมูลไป `staff_place_order` ถูกต้อง, เมนูหมดกดไม่ได้, หน้าครัวแสดงโต๊ะ/กลับบ้าน, หน้าร้านรวมบิลตามโต๊ะและปิดปุ่มชำระจนกว่าจะเสิร์ฟครบ (ยังไม่ใช่ E2E กับ Supabase จริง)
